# 背景地図の画像タイル

地形陰影・市街地・川・湖は公開前に画像化する。プレイ中に標高計算や水域の大量の座標を処理しない。県・市町村・町の境界、文字の衝突判定、役所、本拠地、領土・進捗・選択は別の描画層に残す。元の町形状によるタップ判定、人口、保存形式は変えない。

## 再生成

既存の各取込スクリプトで `assets/data/relief`, `urban`, `water`, `prefectures` と奈良の原本を準備してから実行する。取得済みデータだけを使用し、ネットワークにはアクセスしない。

```sh
/workspace/kunitori-tools/bin/python tools/build_map_tiles.py
```

Pillow と Shapely が必要。`assets/data/map_tiles/` の画像と索引、`assets/data/map_labels/` の名称のみのJSONを生成する。これらをソースとともにコミットして通常のFlutter Webビルドに同梱する。原典の取得日・出典・検証記録は既存の各取込レポートにある。

経緯度に線形な共通グリッドで、画像は256四方、5段階の縮尺（64～1024画素/度）。最細部はおよそ100mで、これ以上の拡大は画像を拡大する。細かい町の形・操作判定は元のポリゴンを使用する。最高解像度から透過を保って縮小し、離島や湖の穴を維持する。

陰影は黒の透過画像に変換する。グレースケールの乗算と同じ暗さになり、Flutterが背景をラスタキャッシュしても町の領土色を覆わない。市街地・水域は別の透過画像にする。

## 実行時

`GeographyTiles` はカメラと画面の画素密度から縮尺を選び、表示範囲と周囲1タイルだけを読み込む。画面が非常に大きい場合は対象を64セル以下に抑えるため解像度を下げる。新しい画像の準備中は最も粗い画像を使用する。

パン・ズームの要求を70msにまとめ、同時デコードは6件、同じ画像の要求は共有する。共通LRUキャッシュは192画像（約48MiBの復号画素）を目標上限にし、表示中の画像を保護する。不要になった画像はdisposeする。地図を閉じた後に完了する処理も表示を更新しない。再試行ボタンで失敗した画像を取り直せる。

背景、領土の塗り、文字・選択枠を別々のRepaintBoundaryに配置する。タップの進捗更新では背景を再生成・再取得しない。境界と地名は拡大時にも読みやすさと選択状態を維持するため、軽量な上層として描画する。

水辺名称は取得時に県境で絞り込み済みの点を使い、県・全国表示で巨大な県境パスとの交差判定を繰り返さない。名称は表示範囲で絞り、1画面48件まで、市町村での形状判定候補は96件までとする。

旧来のGIS原本は取込処理の検証用として保持するが、通常の地図では読み込まない。ブラウザー検証で実際の画像要求と原本への要求がないことを確認する。
