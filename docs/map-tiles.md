# 背景地図の画像タイル

地形陰影・市街地・川・湖は公開前に画像化する。プレイ中に標高計算や水域の大量の座標を処理しない。県・市町村・町の境界、文字の衝突判定、役所、本拠地、領土・進捗・選択は別の描画層に残す。元の町形状によるタップ判定、人口、保存形式は変えない。

## 再生成

既存の各取込スクリプトで `assets/data/relief`, `urban`, `water`, `prefectures` と奈良の原本を準備してから実行する。取得済みデータだけを使用し、ネットワークにはアクセスしない。

```sh
/workspace/kunitori-tools/bin/python tools/build_map_tiles.py
```

Pillow と Shapely が必要。`assets/data/map_tiles_v2/` の旧画像と索引、`assets/data/map_labels/` の名称のみのJSONを生成する。これらをソースとともにコミットして通常のFlutter Webビルドに同梱する。原典の取得日・出典・検証記録は既存の各取込レポートにある。

経緯度に線形な共通グリッドで、画像は256四方、5段階の縮尺（64～1024画素/度）。旧画像の通常の最細部はおよそ100m。現行版は全47県に2048・4096画素/度の拡大用画像を用意し、それ以上は画像を拡大する。細かい町の形・操作判定は元のポリゴンを使用する。最高解像度から透過を保って縮小し、離島や湖の穴を維持する。

陰影は黒の透過画像に変換する。グレースケールの乗算と同じ暗さになり、Flutterが背景をラスタキャッシュしても町の領土色を覆わない。市街地・水域は別の透過画像にする。

## 実行時

`GeographyTiles` はカメラと画面の画素密度から縮尺を選び、表示範囲と周囲1タイルだけを読み込む。画素密度は1.5倍までを解像度選択に使い、細かい段階では対象を12セル以下に抑えるため解像度を下げる。最も粗い全国表示は最大20セル。新しい画像の準備中は最も粗い画像を使用する。

パン・ズームの要求を70msにまとめ、同時デコードは全地図で2件、同じ画像の要求は共有する。共通LRUキャッシュは48画像（約12MiBの復号画素）を目標上限にし、表示中の画像を保護する。不要になった画像はdisposeする。地図を閉じた後に完了する処理も表示を更新しない。再試行ボタンで失敗した画像を取り直せる。

背景は表示中の画面範囲だけをRepaintBoundaryで描画し、拡大した地図全体の巨大な画像を作らない。領土の塗りと文字・選択枠は描画命令を分け、全景のラスタキャッシュは無効にする。タップの進捗更新では背景を再生成・再取得しない。境界と地名は拡大時にも読みやすさと選択状態を維持するため、軽量な上層として描画する。

水辺名称は取得時に県境で絞り込み済みの点を使い、県表示で巨大な県境パスとの交差判定を繰り返さない。名称は表示範囲で絞り、1画面48件まで、市町村での形状判定候補は96件までとする。

旧来のGIS原本は取込処理の検証用として保持するが、通常の地図では読み込まない。ブラウザー検証で実際の画像要求と原本への要求がないことを確認する。

詳細形状は奈良の原本を保持し、その他は1県だけを常駐させる。読込は直列にし、全国の領土は県ごとに必要な町を描画用パスへ変換してから次の県へ進む。元の大きなJSON文字列はAssetBundleの文字列キャッシュに残さない。人口・隣接・保存のメタデータは全県分を維持する。画面を閉じるとネイティブのPath記憶域も明示的にリセットする。

起動時は人口データのJSON行をTownへ変換した直後に解放し、統合後の攻略用隣接グラフができたら、奈良以外の元データ側の重複した隣接文字列も解放する。保存移行に必要な原本ID・人口・町統合対応は残す。毎フレーム生成した地名のTextPainterも描画後にdisposeする。

メモリ回帰の検証: `node test/web/map_memory_test.cjs` はDPR=3、V8 old space上限512MiBで北海道・東京・大阪を2周し、拡大縮小、保存維持、GC後のJSヒープの増加が24MiB以内であることを確認する。2026-10-15の検証では269/224/227MiBから270/226/229MiBだった。これはChromiumの検証であり、iPhone実機のWebKitでの再現確認ではない。

## 奈良の水域スタイル

`restore_nara_water_tiles.py` は元の `WaterLayer` と同じ地図投影（経度方向0.826、1100×1500・余白80）で、水域と河川に外側0.625・内側0.375の地図座標幅を付ける。濃い青 `#123D59` と水色 `#79D9FF`、丸い線端・角、湖の穴を維持して画像に焼き込む。世界座標へ戻す際も縦横の縮尺差を補正する。生成処理本体から呼ばれ、奈良の細かい段階と影響する全国縮小画像を作り直す。

旧 `map_tiles/` と生成専用の `water/`・`relief/`・`urban/` は原本をリポジトリに保持し、現行アプリの配信対象から外す。新しいコードは `map_tiles_uniform/` のlossless WebPだけを使用する。`map_tiles_v2/` も更新前のタブのため保持する。画像サイズ256四方、同時デコード2件、キャッシュ48画像、表示範囲の描画というメモリ制限は共通である。人口・町ID・保存キーは変更しない。

全国表示は専用の `overview` 画像を使用し、約2.5km以上の河川区間と約0.2km²以上の水域だけを表示する。小さな支流・ため池を省き、地形と市街地は維持する。県・市町村の `detail` 画像は従来どおり。全国表示では水域名を描画・読み込みしない。県・市町村表示では名称を維持する。生成は `tools/build_national_water_tiles.py`（全体生成にも組み込み）。

## 全県の解像度統一

```sh
/workspace/kunitori-tools/bin/python tools/prepare_fine_relief.py
/workspace/kunitori-tools/bin/python tools/build_uniform_tiles.py
```

前者だけが国土地理院のDEMを環境のプロキシとTLS検証を使って取得する。zoom 11（奈良と同じ約63m間隔）とし、取得済み原本・中間画像は `data/raw/` に保存する。後者は取得済みデータから全47県を4096画素/度で生成し、下位縮尺もそこから縮小する。奈良の最細部画像は原本の画素を保持する。他県の水域にも同じ物理的な太さ・濃青の縁取り・水色・丸い線端と角を使う。市街地は約100mの原本メッシュを最近傍で配置し、ぼけた低解像度画像の引き伸ばしを避ける。

`map_tiles_uniform/index.json` と `import_report.json` に47県の最高段階・生成数、DEMのzoom、出典、取得日、水域の線幅を記録する。最高段階だけでなく、県表示でも新しいDEMを使う。全国表示は引き続き `overview` の主要水域・市街地と新しい地形陰影を組み合わせる。画像は256四方のlossless WebPとし、同時デコード2件・48画像・表示範囲12セルの制限を維持する。データの人口・隣接・町ID・保存データは変更しない。

配信容量の制約に合わせ、実行時に参照がない旧 `map_tiles/` と生成専用GIS原本はアセット登録から外す。直前版の `map_tiles_v2/` は更新前のタブの画像要求に備えて保持する。原本読込の開発用テストではソースファイルをテスト用アセット経路から読む。

実際の配信では、水域・市街地は4096画素/度、陰影は2048画素/度までのlossless WebPを使う（全県共通）。陰影の元DEMは約63m間隔で、2048画素/度は約40～50m/画素のため元の精度を十分に保つ。より細かい水域画像と一緒に表示するときは陰影の親画像を表示範囲でクリップして使い、情報が増えない4096画素/度の陰影画像は配信しない。全国の主要水域画像は1024画素/度まで。

解像度統一後の検証: 全115件のFlutterテスト、生成画像の4件のPython検証、ブラウザで保存・検索・切替・再読込が成功。DPR=3・V8 old space上限512MiBで北海道・東京・大阪を2周（大阪は7段階拡大して高精細画像を検証）し、GC後ヒープは278/233/235MiBから278/234/237MiB。配信前に `python tools/check_release_geography.py` でGIS原本への実行時参照がないことと、1GiB未満の公開容量を確認する。
