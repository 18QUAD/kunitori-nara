# くにとり — 全国版

全国47都道府県・1,896市区町村（政令指定都市は区単位）の実在する町を攻略するソロ陣取りゲーム。
2020年国勢調査境界の人口合計は126,146,099人。人口1人＝1タップ、人口0は1タップです。
奈良県の3,078町丁字から統合した町・大字、人口合計1,324,473人と既存の保存データを維持しています。

## 起動

Flutter 3.29.3 / Dart 3.7.2で検証。

```sh
flutter pub get
flutter run
```

Androidは接続端末を選択。iOSの実行・署名はmacOSとXcodeが必要です。
Android NDKはshared_preferences_androidに合わせて27.0.12077973を指定しています。
Androidの配布用署名・アプリIDは本番公開前に設定してください。現在は開発用署名です。

```sh
flutter test
flutter analyze
flutter build apk --debug
flutter run -d chrome
flutter build web --release
python3 tools/prepare_map_cache.py build/web
```

APK: `build/app/outputs/flutter-apk/app-debug.apk`

## 遊び方

1. 画面上部の固定領域（約60%）で市区町村→町を選び、難易度と本拠地を決定。地図／戦績タブで上部だけを切り替え、下部のtipsとタップ領域は維持。
2. 金色の隣接地域を選択し「タップで進軍」。境界線は白、選択中・攻略中の枠線は赤、緑は自領。県全域では攻略先の市町村を赤枠で示します。
3. 画面下の2行の地域tipsを読む。5秒ごとに次の情報へ自動で切り替わる。町の選択を変えると最初のtipsから再開。
4. 市町村の全町を獲得後、役所・役場のある町、または役所の地図記号をタップして開始確認を開く。開始前はキャンセル可能（領土喪失なし）。最後の町を獲得しても自動では始まりません。
5. 4択5問を出題し、5問すべて正解で市町村制圧が確定。紙吹雪と「制圧成功」、市町村名を表示し、「地図へ戻る」で結果を閉じます。不正解・時間切れはその時点で終了し、役所所在地の1地域だけ支配を失います。本拠地と重なっていても対象です。本拠地の位置・累計実績は保持し、役所所在地を再攻略すると再挑戦できます。

難易度は本拠地決定時に固定。1タップで1人分進み、攻略途中も人口に加算。必要タップ数は `max(1, 人口)`。人口0の地域は1タップ。本拠地の人口は開始時に加算。
難易度はクイズの各問に適用し、旅人25秒、武将15秒、天下人8秒。市町村ごとの出題可能な問題から重複なしで5問を選び、選択肢も並べ替えます（表示済みtipsに限定しません）。
旅人にはネタ選択肢、武将・天下人には紛らわしい選択肢を用意。
現在の設問、正解数、残りの設問、締切を保存します。各問の締切は絶対時刻で、バックグラウンド移行や再起動では延長されません。旧版の進行中の1問クイズは、その問題と締切を維持して4問を追加します。既存の領土・制圧済み市町村・累計実績は引き継ぎます。

## 全国の地図と攻略

上矢印で市区町村→県→全国と1段上の地図へ戻れます。全国では県境を表示し、緑・攻略途中の色は町の領域だけに付きます。県→市区町村→町と選択でき、検索は県名・市区町村名・町名に対応します。家アイコンで本拠地または攻略中の町へ戻れます。攻略開始後も「設定 → 地名から探す」から検索できます。

陸続きでない地域ごとに、人口最大の町（同数なら町ID順）を「渡航の入口」に設定します。まだ自領がない地域の入口は、本拠地決定後、通常と同じ人口分のタップで攻略できます。入口獲得後は実際の陸上隣接に沿って攻略します。本拠地を離島に置いた場合も本州への渡航が可能です。渡航は実データの隣接関係を書き換えません。

奈良県以外の全1,857市区町村に1〜5件、計3,582件の短文tipsを収録しています。役所・役場のマークは全国で表示しますが、奈良県以外の制圧クイズは準備中です。全町獲得は可能です。奈良の制圧クイズとtips IDは従来どおりです。起伏・市街地・川・池・湖は全国・都道府県・市区町村で、山名は全県の県・市区町村マップで表示できます。

全国の人口・隣接メタデータと県境は起動時に読み込み、町・市区町村の描画形状は県ごとに遅延読み込みします。全国データの再生成手順：

```sh
python -m venv /tmp/kunitori-import
/tmp/kunitori-import/bin/pip install 'shapely>=2,<3'
/tmp/kunitori-import/bin/python tools/import_japan.py
# 原本キャッシュが揃っている場合は --offline
```

対象コードはCODHの2020年公式索引（1,896件）と照合済みです。`assets/data/japan_import_report.json` に県別人口・件数、県境隣接、原本SHA-256を記録します。市区町村ごとに独立して作成された原本境界は、完全一致する線に加え、約1m以内で相互に約10m以上並行する元線分を照合し、点接触を除外します。奈良県内の既存隣接は維持します。全47県、全国人口、奈良の原本ID・人口の一致を検証してからデータを有効化し、`assets/data/nara.json` は書き換えません。

## 背景・境界線の事前生成

地形・市街地・水域を一体化した背景と、透明な境界線画像を公開前に生成します。端末は512pxの完成画像をデコードして表示し、水域・県境のバイナリや画像生成用のパスを読み込みません。境界線は領土色の上、地名・役所・選択枠の下です。地形を非表示にしても境界線は残ります。全国は主要河川・湖のみで、水域名は表示しません。

画像の倍率は2倍刻みで、＋／−ボタン1回と画像1段階を一致させます。ピンチ終了時と旧保存の復元時も近い段階へ揃えます。全国はレベル−3〜5、県は−3〜7、市区町村は−3〜8を使い、完成画像の上限を超える拡大は行いません。境界線は各段階で約0.625論理ピクセルの白線として生成し、拡大前の太い画像が一瞬出ることを防ぎます。水域を含む細かい区画は元の輪郭から個別に生成し、水域のない区画だけ同じ地形・市街地の親画像を再利用します。海は背景画像の透明部分です。県境は従来の共有線網を使い、隣接県を二重に描きません。

画像予算は32／64／128／256MiB、初期値32MiBです。1/8を圧縮データ、残り7/8を背景・境界線の共通LRUへ割り当てます。表示中の画像を固定し、現在の前後1段階を優先して空きを使います。足りない場合は離れた段階・古い地域の画像から解放します。読み込み完了や地図切り替えのたびには全消去せず、離れた画面で使った画像も予算内なら再利用します。デコード中の確保も予算に含め、古い描画フレームの終了後に固定を解除します。広い画面でセル数が増える場合はデコード寸法を抑えます。領土・進捗・選択の変更は背景・境界線の読み込みを開始しません。全国の攻略メタデータ、表示中の県形状、Flutter本体・描画エンジン等のメモリは、この画像予算とは別です。

完成画像は `data/prepared_maps/` の最大1MiB単位のパックに保存します。Flutterのアセット一覧へ全画像名を展開せず、地理インデックスと少数のパック名だけを登録します。Android等ではアプリに同梱した同じパックを読み、Web公開時は重複する同梱分を取り除きます。Workerも短い画像名と型付き配列で位置を保持し、パックのSHA-256で内容を検証します。初回保存はゲーム開始前に完了させ、以後は端末の保存済みパックを使います。新しいパックが揃った後の旧画像キャッシュの整理はゲームの保存データを削除しません。

背景は512pxのWebP、境界線は透過の可逆WebPです。画像パックが750MiBを超える場合、Pagesのサイト容量上限に収めるため、初回保存用の画像だけ同じリポジトリの固定コミットから取得します。画像を先にソースへコミットしてからWebを準備してください。配信先はマニフェストの `packBaseUrl` に記録し、保存後の読み込みとキャッシュキーは配信元によらず共通です。地理インデックスは画像パックに詰めず、他のランタイムデータと同じ最大1MiBの圧縮チャンクで保存します。

既存の許可済みGISだけからの再生成（時間がかかります）:

```sh
dart run tools/export_border_groups.dart
python -m pip install 'shapely>=2,<3' Pillow numpy
python tools/bake_map_images.py --workers 4
```

水域・市街地の原本が変わる場合は先に既存の取込処理と `tools/prepare_cached_water.py` を実行します。描画ルールを変える場合は生成先 `assets/data/map_images/*.webp` と作業用 `data/raw/baked_borders/` を再構築します。完成パックからの通常の公開ビルドでは再生成は不要です。

```sh
flutter build web --release --base-href /kunitori-nara/
python tools/prepare_map_cache.py build/web
python tools/check_release_geography.py
```

元の町ID・人口・隣接・ゲームの保存キーは変更しません。テストは完成パックから必要な画像だけを読み込み、通常のタップ・領土獲得・縮尺の往復での再利用と、オフライン読み込みを確認します。

## 保存

端末内のshared_preferencesに、領土・本拠地・進行中タップ・表示済み情報・クイズ・称号・累計値を保存。
連続タップ時の書き込みは直列化・集約。失敗時は画面に再試行ボタンを表示。
破損・未知バージョンのデータは上書きせず読み込みエラーを表示します。
端末間同期・サーバーバックアップはありません。アンインストールやデータ削除には耐えません。
Webプレビューの保存とスマホ端末の保存は独立しています。

## データ出典と加工

[国勢調査町丁・字等別境界データセット（CODH作成）](https://geoshape.ex.nii.ac.jp/ka/)
「令和2年国勢調査町丁・字等別境界データ」（e-Stat）を加工。
doi:10.20676/00000450 / [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

奈良県の従来データでは、同じKEY_CODEの分割領域を統合し、人口・面積を合算。描画形状はDouglas–Peucker法で簡略化。
隣接グラフは簡略化前の共有線分（経緯度小数6桁）から計算し、点接触を除外。
統合後の全1,858町領域の到達可能性、隣接の対称性、県人口・面積合計、旧保存データの移行をテストしています。
法的・測量用途の境界ではありません。町丁字の名称・境界は2020年時点です。

```sh
python tools/import_nara.py
```

原本は`data/raw/`にキャッシュ（Git対象外）。生成レポートは`assets/data/import_report.json`。
地図データと日本語フォントは同梱し、Androidではネット接続不要。

奈良県の地域tipsには、全39市町村に各30件、計1,170件を収録しています。
自治体公式資料の既存90件を残し、日本語版Wikipediaの57記事から要約・編集した1,080件を追加しました。
攻略中の町がある場合は、その市町村の情報を優先し、続いて既存の文化・県共通の情報を表示します。
攻略中でない場合は選択した町・市町村（未選択なら本拠地）の情報を表示します。
tipsは40文字以内に要約し、幅320pxの画面でも通常の文字サイズで2行に収まるようにしています。
全文表示・タップ操作はありません。tips本文に出典・URL・脚注は表示しません。出典一覧は設定の説明画面にあります。
人口関係の情報はtipsに表示しません。既存の情報ID・保存データを保持しています。WikipediaのIDは原稿の固定ID列で管理し、文章の修正では変えません。
地域tipsは閲覧用で、クイズには既存の設問付き情報を使用します。

Wikipedia由来のtipsは、日本語版Wikipediaの各記事の執筆者による内容を要約・編集したもので、
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)に従って提供します。
各tipsの出典は参照した記事の固定版URLで、記事の履歴から執筆者を確認できます。
出典一覧・取得日・取得HTMLのSHA-256は `data/tips/wikipedia_sources.json`、編集原稿は `data/tips/wikipedia.tsv` に記録しています。
公式資料の出典は `lib/regional_tips.dart`、Wikipediaの出典は `lib/wikipedia_tips.dart` の各項目にあります。
Wikipedia取得日は2026年10月8日（UTC）。伝承・諸説は断定せず、営業情報・人口など変動しやすい内容を避けています。
記事や関連記事を読み、短文として個別に編集したデータを同梱するため、プレイ中のネット接続は不要です。

原稿変更後の生成・検証：

```sh
python tools/import_wikipedia_tips.py
dart format lib/wikipedia_tips.dart
python tools/import_wikipedia_tips.py --check
```

## 全国の地域広告（楽天API）

表示中の県・市区町村のtipsと同じ地域に合わせて広告を表示します。県外を閲覧していない場合は攻略中の町、未選択なら本拠地を優先します。
通常のtipsを3回表示した後、4回目に具体的な商品・返礼品・宿泊施設のPRカードを5秒表示します。
広告も通常のtipsと同じキャラクター横の吹き出し内に収め、表示切り替えで領域の高さやキャラクターの位置を変えません。
長い商品名は省略し、狭い画面や文字拡大時には広告内容を領域内に縮小して表示します。
カードをタップすると楽天の詳細ページを別画面で開きます。クイズ・制圧演出中、tips非表示時には広告を表示しません。
カード内のタップは表示した商品・施設だけを開き、押している間に表示が更新されても押し始めた広告のURLを維持します。
ゲーム進行・保存データを楽天へ送りません。取得APIに送るのは市町村IDだけです。

GitHub PagesにはAPIキー・楽天から取得した商品データを保存しません。
`server/regional-ads/` のCloudflare WorkerがAPIを呼び、表示に必要な名称・画像URL・広告URLのみを返します。
サーバーとアプリのキャッシュは最長1時間。アプリが保持する広告は直近3市区町村までです。失敗したカテゴリーは非表示にして5分後に再取得します。
設定未完了・通信失敗・期限切れのときは通常のtipsを表示します。架空の広告や報酬の付かない代替リンクは表示しません。

全国47都道府県・1,896市区町村（2020年の地図区分）に対応します。地元企業は所在地の確認済みショップに限定し、初期登録は奈良市（ふとんのマルソウ）、
橿原市（大和まほろば 本舗）、桜井市（三輪そうめん小西・三輪山勝製麺）です。
返礼品は確認済み自治体ショップを優先し、未登録の市町村は検索結果のショップ名が対象自治体名と完全一致し、ショップコードの自治体番号も一致する場合のみ採用します。政令指定都市の行政区の返礼品は所属する市、東京都の特別区は各区のものを表示します。
宿泊は施設の住所が対象の都道府県・市区町村に一致する場合のみ採用します。結果がない地域には他地域の広告を出しません。
ショップの地域対応と確認元URLは `server/regional-ads/regions.json` に記録しています。全国の地域区分は `python tools/build_ad_regions.py` でゲームの自治体一覧から再生成できます。新たな民間ショップを推測で追加しません。

### 稼働開始の手順

1. [楽天アフィリエイト](https://affiliate.rakuten.co.jp/)の利用サイト情報に `https://18quad.github.io/kunitori-nara/` を登録します。
2. [楽天ウェブサービス](https://webservice.rakuten.co.jp/)でアプリを登録し、アプリID・アクセスキー・アフィリエイトIDを取得します。
   アプリの許可サイト／Originに公開サイトの `https://18quad.github.io` を設定し、トラベルAPIの利用承認が必要な場合は申請します。
3. Cloudflare Workersを用意します。GitHubリポジトリの Settings → Secrets and variables → Actions に次のSecretsを登録します。
   `RAKUTEN_APPLICATION_ID`、`RAKUTEN_ACCESS_KEY`、`RAKUTEN_AFFILIATE_ID`、`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。
   Cloudflareのトークンは対象アカウントのWorkersを編集・公開できる権限を設定してください。値はソースやチャットに貼り付けません。
   初めてWorkersを使う場合は、Cloudflareの Workers & Pages → Create application → Start with Hello World から、
   `kunitori-nara-regional-ads` という名前で一度Deployし、`workers.dev` の初回設定を完了してください。
   このHello Worldは次の手順で楽天広告APIに置き換わります。
4. GitHub Actionsの **Deploy regional ads API → Run workflow** を実行します。
5. 公開されたWorkerの `https://kunitori-nara-regional-ads.<自分のサブドメイン>.workers.dev/ads` を、
   同じ設定画面の **Variables** に `REGIONAL_ADS_ENDPOINT` として登録します。このURLに秘密情報を含めません。
6. **Publish Flutter Web → Run workflow** を実行します。公開後、奈良市などを攻略し、4回目のtipsでPRカードが出ることを確認します。

キー取得・Worker公開・エンドポイント設定が完了するまでは広告非表示です。
広告取得は地域選択時とキャッシュ期限後に自動実行され、個別商品の登録やリンク発行は不要です。
APIの表示・素材利用条件と掲載商品の成果報酬対象は楽天の最新条件に従います。
宿泊画像はAPIで取得し「楽天トラベル」を画像左下に表示します。価格・空室・寄付額はカード内では表示しません。

## 地形の起伏

## 河川・湖沼

山のボタンで起伏・山名・川・池・湖をまとめて表示・非表示にできます（初期表示はオン）。
[国土地理院ベクトルタイル提供実験](https://github.com/gsi-cyberjapan/gsimaps-vector-experiment)の
`river`・`waterarea`・`label` レイヤーから、地表の河川・人工水路、湖・貯水池、河川・湖沼の注記を抽出しました。
提供元の更新情報は2026年7月1日時点。河川・水域はズーム11、町表示用の川名・湖沼名はズーム14も使用し、取得日と加工条件を
`assets/data/nara_water.json` の `metadata` に記録しています。

水域は青色、河川は水色の線で描画し、市区町村マップでは詳細な川名も表示します。町名と重なる場合は近くの空き位置を探し、重なりが解消できない注記は省略します。
地下水路・枯れ川は含めず、全ての細流を網羅するものではありません。河川の線幅は見やすさのため調整しています。
県境で形状を切り出し、市町村表示では選択地域内に描画。元データの島・中州の穴は保持しています。
境界・領土の選択・隣接判定・進軍ルールは従来どおりです。データは同梱し、表示時の外部通信は不要です。

```sh
python -m pip install mapbox-vector-tile shapely
python tools/import_water.py
python tools/import_water_labels.py
```

原本は `data/raw/water/` にキャッシュされます。出典：国土地理院ベクトルタイル提供実験を加工して作成。

県マップ・市町村マップとも川を明るい水色＋濃い縁取りで表示し、領土色や起伏から見分けやすくしています。川と縁取りの太さは地図座標で固定し、地図と同じ倍率で拡大・縮小します（4倍表示で水色1.5px・縁取り全体2.5px）。画面上の最低線幅や県・市町村別の補正は設けません。線データと細長い水面ポリゴンの両方に同じ描画を適用します。

## 山名

### 診断ログの自動回収

`web/diagnostics.js` は起動時（約2秒後）、約1分ごと、バックグラウンド移行時に
既存Workerの `/diagnostics` へ直近の端末内ログを送信します。
旧版で端末内にのみ保存したログも、新版の起動時に回収します。通信失敗時はローカルに残し、
次回の送信で再試行します。一度に送信するのは最大40KiB、同時送信は1件です。

送信対象は表示中の地図座標・地域ID、操作時刻、攻略状況の件数・ID、エラー、画像キャッシュ、
取得可能なメモリ情報、ブラウザ情報、ランダムな識別IDです。
ゲームのセーブ本体や認証情報は送信しません。メモリ情報が取得できない場合はnullを保持し、
終了通知の欠落をメモリ不足と断定しません。

保存先はWorkerの非公開SQLite Durable Objectです。最新128端末、各端末の直近最大3起動分に制限し、
7日経過した記録を削除します。外部からの参照にはサーバーの認証トークンが必要です。
公開ページには認証トークンを含めません。

管理者は既存GitHub認証で次を実行できます（既定はiOSの新着最大5件）。

```sh
node tools/diagnostics/fetch.mjs /workspace/remote-diagnostics.json
# 全プラットフォーム
DIAGNOSTICS_PLATFORM=all node tools/diagnostics/fetch.mjs /workspace/remote-diagnostics.json
```

既存の `Deploy regional ads API` ワークフローの `export` 操作が、GitHub Secretsの資格情報で取得します。
返却ログはローカル生成の一時公開鍵とAES-GCMで暗号化し、暗号文だけをGitHubのcheck結果へ書き込みます。
ローカルの秘密鍵で復号し、読み取り権限を制限したJSONへ保存します。
利用者によるファイル添付は不要です。ブラウザが新版を一度も実行していない端末のローカルログは、
新版の起動までサーバーには届きません。

地図画像は初回起動後に全国分を CacheStorage へ自動保存します。
初回保存中はメッセージと保存済み容量に基づく進捗バーを表示し、保存完了後にゲームを起動します。
保存処理は最大2件で行い、描画エンジンと全国攻略データの読み込みを同時に走らせません。
次回以降は保存済み画像を優先し、画像内容のハッシュが変わった分だけ取得します。
ダウンロードが中断した場合も保存済み分から再開します。画像を一括デコードしません。
Web ビルド後は上記の `prepare_map_cache.py` を必ず実行してください。
保存先はブラウザ管理のため、サイトデータが削除された場合は不足分を再取得します。
